# 外部 AI 科研计划导入

ResearchFlow 1.3.0 提供可复制的科研计划协作提示词和外部计划导入。提示词自动带入当前项目名称和已设置的目标日期；项目背景等其他资料由用户主动补充。软件不包含 AI 模型、不连接 AI 平台，也不会自动汇总或发送项目资料。

## 使用方式

1. 在“科研项目”中展开一个进行中或已暂停的项目，打开“AI 科研计划导入”。
2. 项目名称与已设置的目标日期自动带入。在提示词上方填写项目资料；未知内容写“尚未确定，请 AI 协助讨论”。填写值自动进入提示词最前面；未填时复制会集中提醒，也可明确选择复制待填模板后在发送前补充。展开预览可编辑协作要求，表单变化不会覆盖自定义要求。
3. 与 AI 讨论大阶段目标及其预期成果，把阶段内的小目标拆成具体行动。确认后发送“计划已确认，请输出 ResearchFlow 格式”，让 AI 交付 `researchflow-plan` version 1 的 UTF-8 JSON 文件；AI 无法提供附件时，复制完整 JSON 文本即可。
4. 回到 ResearchFlow，粘贴 JSON 或选择不超过 1 MB 的 JSON 文件，查看预览。
5. 逐项选择阶段和行动；可以将阶段映射到已有阶段，仅追加行动。确认后一次性保存。

导入只向当前选中的项目添加新记录，不改变现有项目字段或阶段内容。未填写单次参考时长的行动按 10 分钟创建。阶段日期可选；普通行动没有目标日期字段，因此协议不导入行动日期。计划时段需要用户继续使用现有科研规划页面单独创建。

## 提示词中的目标与交付

提示词明确区分两类内容：“项目最终成果与验收标准”是研究本身要达到的成果，由用户补充；“本次 AI 协作的最终交付”是可导入软件的结构化科研推进计划 JSON 文件，已在提示词中固定说明。

当前协议使用两层结构：大阶段目标放在 `milestones`，其名称、说明与预期成果对应 `name`、`description`、`outcome`；小目标拆成该阶段下的 `actions`，行动名称写可执行的动作，`note` 写小成果、完成标准或第一步。该交换协议不包含嵌套子阶段字段；导入后可在项目流程图中调整阶段层级。提示词要求先讨论和修订，再经用户明确确认输出 JSON；日期及工时未知时省略，避免编造精确安排。

“准备提示词”和“导入计划”页面的复制按钮都复制同一份前置资料加协作要求。关闭导入窗口不会保存填写草稿；已有项目科研记录不被改写。

## 隐私

复制到外部 AI 的内容由相应平台处理。不要向不适合的平台发送患者身份信息或保密研究内容。ResearchFlow 不会因为使用此功能而自动连接 AI，也不会读取项目文件。

## 导入前副本

计划导入和备份恢复会在原子写入时将当前完整数据保存为同一份导入前副本。桌面版副本位于应用数据目录中的 `researchflow.before-import.json`；浏览器预览使用独立的 localStorage 项。可在“设置 → 备份与恢复”恢复最近一次副本。再次恢复会先用当前数据替换这份副本，便于回退一步。

这是一份完整应用数据备份，不是只含计划的文件。恢复前应确认项目、行动、成果卡、专注记录等都会回到该副本时点的状态。

## 格式摘要

- `format` 固定为 `researchflow-plan`，`version` 当前为 `1`。
- `projectName` 和 `projectType` 是可选说明，只用于确认，不用于选择目标项目。
- 阶段与行动名称和类型使用自由文本，不按研究类型套模板。
- 阶段日期可选；任务可选单次分钟数、预计总工作量和备注。
- 每份计划最多 50 个阶段、500 项行动，JSON 不超过 1 MB。
- 外部 ID、项目状态、已有数据更新指令不受支持。记录 ID 和状态由 ResearchFlow 创建。
- 未识别字段会警告并忽略；无法确认结构的内容应让外部 AI 按协议重输。
