# ResearchFlow 隐私与数据安全

适用版本：1.7.2 · Windows 桌面版

## 你的科研记录，由你掌控

ResearchFlow 在本机管理项目、阶段、行动、时间计划与研究记录，无需注册账号。应用不会自动将科研项目内容上传至开发者服务器。欢迎页和设置中的“了解科研数据安全”可随时打开这份说明的应用内版本。

## 记录保存在哪里

正式桌面版的数据通常位于 `%APPDATA%\com.researchflow.desktop\researchflow.json`，以设置 → 本地数据位置显示的实际路径为准。直接运行 EXE 也使用该 Windows 账户的应用数据目录；数据不会跟随程序自动移动。浏览器开发预览使用独立 localStorage，不是正式桌面数据。

项目关联的文件路径只用于记录线索。软件备份不会自动包含这些路径指向的数据集、脚本、文档或图表，换电脑时需另行复制。

记录和备份是普通 JSON，未采用 ResearchFlow 应用层加密。获得相应文件权限的其他程序可能读取它们。共享设备、网络目录或云盘中的访问范围由相应系统及服务控制。

## 离线功能与安装联网条件

项目规划、行动管理、专注计时和本机备份恢复可以离线使用。首次安装时，若电脑缺少 Microsoft Edge WebView2 Runtime，安装程序可能联网下载运行库。用户主动访问网络盘或外部 AI 服务时，也可能需要网络。

当前应用没有云同步、自动更新检查、科研内容上传、应用遥测或错误上传功能。上述结论来自当前源码与打包配置审查，不是对操作系统、运行库、第三方软件或未来版本网络行为的保证。

## 外部 AI 与主动分享

AI 计划导入在本机准备提示词、复制到剪贴板，并读取用户选择的计划 JSON。ResearchFlow 不内置模型、不需要 API Key、不直接连接 AI 服务。

状态回顾可在本机按自然周生成科研进度Markdown或外部AI总结提示词。生成内容仅来自你勾选的项目和本地记录；复制或导出前会显示隐私确认。软件不会自动连接AI服务或发送内容。当你主动把内容发送给第三方 AI 或其他平台时，内容将由该平台处理。发送前检查未公开研究信息、患者身份信息和其他不适合外发的资料。剪贴板及云盘也受相应系统或第三方设置影响。仅仅把软件安装包交给别人不会把你的科研数据一并交给对方。

## 备份与恢复

设置 → 导出 JSON：选择可信保存位置。恢复前先导出当前记录，再检查合并或覆盖的范围。应用保留上一次写入前的数据，以及最近一次导入、恢复或示例移除前的本地安全副本；这些副本不能替代长期、独立的手动备份。

升级使用原有应用标识与本地数据目录。首次读取1.7.2时，在 `backups/before-1.7.2/` 中保留已有科研JSON原文和窗口偏好；创建副本失败时停止写入并显示错误。副本与当前记录具有同样的隐私属性，请一起保护。寄语只保存在本地设置中；项目流程图读取同一份项目、阶段与行动，不上传或复制科研记录。

不要在程序运行时手动替换数据文件。导出到云同步目录、共享目录或代码仓库前，应确认访问与分享范围。

## 使用 AI Agent 与 Git 时

### 文件访问取决于授权范围

Codex、Cursor、Claude Code 等工具获得文件访问权限后，可能读取授权范围内的科研资料。是否向外传输取决于工具能力、权限配置、用户指令和实际操作。

只授权当前工作所需目录，避免无必要地开放整个用户目录或磁盘。敏感文件读取、网络发送或 Git 推送前，检查目标与内容，并保留必要的人工确认。ResearchFlow 不监控或拦截第三方 Agent，也不代替操作系统管理权限。

### 添加、提交与上传有区别

`git add` 将文件加入暂存区；`git commit` 将暂存内容写入本地历史；`git push` 才将相应提交发送到远端。执行前核对文件、远端地址与仓库可见范围。

以下为可自行执行的只读检查，ResearchFlow 不会自动运行：

| 命令 | 用途 |
| --- | --- |
| `git status` | 查看变更与暂存状态 |
| `git diff --cached --name-only` | 查看本次暂存文件名 |
| `git ls-files` | 查看已被 Git 跟踪的文件 |
| `git remote -v` | 核对远端仓库地址 |

重点检查科研项目 JSON、备份、论文草稿、实验结果和含私人信息的配置。JSON 也可能是合法工程配置，不应一概忽略所有 JSON。

### .gitignore 的作用与边界

.gitignore 主要影响尚未跟踪文件是否被普通 Git 添加流程纳入版本控制。它不是文件访问权限设置，不能阻止 Agent 读取、其他程序复制或直接发送文件；强制添加也可能绕过规则。

后补忽略规则不会自动停止已跟踪文件的跟踪，不会删除提交历史，也不会撤回远端副本。

### 如果内容已经上传

先停止继续上传或分享，核对相关提交、远端仓库及访问范围，再按具体情况处理。清除工作区文件或添加忽略规则，不代表历史与远端副本已清除；已有复制也可能仍然存在。ResearchFlow 不提供自动移除 Git 跟踪、历史重写或强制推送功能。
